# FH3X 产品最新点位适配开发计划

日期：2026-09-18  
需求来源：`HA可参考注册实体.xlsx`  
状态：第一阶段已实现（点位归一化、日/月统计和展示分档）；协议待确认项及真机验收仍未完成。

当前实现文件：`custom_components/pylontech_fh3x/product.py`、`period_stats.py`。
逐项映射见：[FH3X 产品点位映射矩阵](FH3X产品点位映射矩阵.md)。

已完成的第一阶段内容：

- 产品名称到现有协议值的兼容映射，包含单位换算和设备故障优先级；
- BMS 允许充放电功率计算；
- PCS、PV、AC、电表、BMS 的明确只读点位注册及中英文翻译；
- 日/月累计量基线持久化，重启、计数器回退和通信间断不会伪造增量；
- Compact/Standard/Engineering 分档接入新增实体；
- 映射单元测试、编译、Ruff、仓库校验和原有 71 项测试通过。

## 1. 目标与实施基线

以产品表中的 **104 个实体定义**为需求清单：75 个 sensor、3 个 binary_sensor、5 个 switch、8 个 number、5 个 select、8 个 time。

采用已确认原则：

- 全部纳入适配清单，按档位展示；存在协议冲突的点位先隔离，明确标注未完成。
- 保留表外已有实体、唯一 ID、用户命名、禁用选择及历史统计。
- 继续面向 HACS，不增加自定义面板。
- 基于当前 HACS `main` 的内置通信实现开发，依赖保持 `pymodbus`；保留 `shared-library` 实验分支，不引入其未发布依赖。
- 不将“104 行需求”直接等同于“新增 104 个实体”，已有同义实体优先复用。
- 保持 PCS 地址 `2`、BMS 地址 `1`，不擅自修改已有 Modbus 地址。

## 2. 实体与协议调整

### 2.1 建立逐行映射清单

每行记录：产品 Key、现有 Key、实体类型、读取来源、单位、展示档位、实现状态及测试结果。

重点兼容映射：

| 产品定义 | 处理方式 |
|---|---|
| `pv_power`、`pv_generation_energy` | 复用 `pv_total_power`、`pv_total_energy` |
| `operation_mode` | 复用 `ems_mode` |
| `schedule_*` | 复用现有 `period_*` 系列 |
| `battery_soc_bms` | 新增 BMS SOC，保留现有 PCS SOC |
| `charge_cutoff_soc` | 复用 `charge_limit_soc` |
| AC 相电压、相电流、交流频率 | 复用对应地址的现有实体，修正默认名称和说明 |

已有功率实体保持原生 W，避免影响自动化；通过 HA 支持的显示单位提供 kW。新增实体按产品表明确单位，不能仅改单位标签而不换算数值。

### 2.2 补充明确的点位

- 增加型号、序列号，以及尚未注册的 AC 功率、无功功率、视在功率、功率因数、电表电压和频率。
- 增加最大允许充放电功率，使用已解码的 BMS 电压、电流计算；缺失、非法值不参与计算。
- 增加第三方光伏三相合计功率，各相按 S32 解码，验证后换算为 kW。
- 补齐 BMS SOC、计划星期等实体的展示、翻译和属性。
- 沿用并机 PCS 容量与单机 BMS 容量选择规则。
- 新增可选读取块安排在对应 PCS/BMS 请求组内，读取失败仅影响相关实体。

### 2.3 隔离待确认项

以下项目进入问题清单，不根据表格中的矛盾信息新增写入：

| 待确认项目 | 冲突或缺失信息 | 本轮处理 |
|---|---|---|
| 放电截止 SOC | 第 78 行 `40904` 与当前 EPS 启用地址冲突，需确认是 `40903`、`40905`，还是另有定义 | 保留现有 SOC/EPS 控制，不按冲突地址新增写入 |
| 取电/馈电限制 | 类型为 number、权限为 R；BMS 地址解释、可写性、范围需确认 | 确认读取语义后可实现只读数据；写入暂不开放 |
| 热泵和 EMS | 权限为 R，与控制类型及功能码描述冲突 | 保留现有控制实现，不扩大权限 |
| 最大无功功率 | 单位未确认 | 暂不注册计算后的正式实体 |
| 第三方光伏功率 | 类型栏为 Float32，备注明确各相为 S32 | 以协议核对 S32 解码并增加测试 |
| 第三方光伏累计量 | `0x06ED–0x06EE` 是否为偏移、基址和单机适用性待核实 | 确认前不新增地址读取 |
| 型号能力 | 单/三相、PV3、兼容电表的识别依据不完整 | 由明确型号或协议证据判断，不将零值视为不支持 |

每个隔离项关闭前，该项及依赖它的统计实体均不得标记验收通过。产品表用于需求定义，协议地址、类型和写入行为仍须结合协议与设备证据核实。

## 3. 统计、告警与展示

### 3.1 日/月电量

新增表内 8 类电量的日、月统计，共 16 项：电池充电、电池放电、光伏发电、第三方光伏发电、逆变器发电、逆变器耗电、电网购电、电网馈电。第三方光伏统计随其数据源确认后启用。

- 使用经过累计量保护的有效数据更新统计，不增加 Modbus 读取。
- 按 HA 配置时区切日、切月，并按配置项持久化累计值、周期及数据完整性。
- 首次安装从首个有效样本开始，标记为“不完整周期”，不伪造零点基线。
- 同周期重启恢复统计；跨周期离线无法准确分配的增量不强行归入新周期，并标记不完整。
- 累计量回退、异常跳变、通信缓存不得造成负数或重复累计。
- 逆变器累计耗电量由负向 AC 功率积分得到，明确标注“估算”；不跨离线或重启间隔积分，也不将其解释为逆变器自身损耗。

### 3.2 告警聚合

- 新增设备综合状态、设备故障、设备告警和当前告警代码。
- 综合状态优先级为故障、告警、正常；无法确认正常时显示不可用。
- 按产品表，聚合“设备告警”在故障存在时不亮；原 PCS/BMS 告警实体继续独立显示。
- 合并代码时保留 PCS/BMS 来源，详细列表放属性，避免状态文本过长。
- 复用现有告警历史机制，避免新增聚合实体重复写入事件。

### 3.3 分档与兼容

| 档位 | 展示内容 |
|---|---|
| 日常 | 总功率、核心累计量、SOC/SOH、容量、综合健康状态及并网状态 |
| 常用 | 日/月统计、温度、允许充放电功率、PV/AC/电表分相数据 |
| 工程/诊断 | 身份信息、无功/视在功率、功率因数、原始代码及其他工程点位 |

- 控制继续沿用日常、常用设置、高级计划三档，详细计划保持高级开放。
- 保留现有档位配置值与用户覆盖设置；补齐英文、简体中文文本。
- 已知不支持的型号不新增相应实体；已有相关实体保留 ID，并标记不可用，不删除历史。
- Energy Dashboard 配置不自动迁移或覆盖。

## 4. 测试与验收

1. **逐行覆盖：** 104 行全部得到“复用、新增、待确认”结论，每项有协议依据和验收状态。
2. **协议测试：** 覆盖地址、偏移、U16/S16/U32/S32、倍率、正负功率、并机容量和无效值。
3. **统计测试：** 覆盖首次安装、重复样本、重启、离线、跨日/月、夏令时、累计归零和异常跳变。
4. **告警测试：** 覆盖正常、故障与告警并存、数据缺失、未知位及历史去重。
5. **兼容测试：** 验证实体唯一 ID、用户命名、禁用设置、既有自动化和 Energy Dashboard 无回归。
6. **控制测试：** 覆盖四组计划、星期位掩码、功率编码、串行写入、读回失败及快速切换。
7. **检查流程：** 运行编译、单元测试、Ruff、仓库校验，并针对最终候选执行 Hassfest/HACS 校验。
8. **Green 验收：** 备份后部署，记录设备型号、固件和拓扑；核对实体和实测值，验证重启、升级回退及持续运行。写入测试限定已确认的安全点位，记录原值并恢复。

本地检查命令：

```bash
python3 -m compileall -q custom_components tests scripts
python3 -m unittest discover -s tests -v
ruff check custom_components tests scripts
ruff format --check custom_components tests scripts
python3 scripts/validate_repository.py
```

模拟器结果与真机结果分别记录；未执行的验收不得标记通过。

## 5. 实施顺序与交付

1. 建立产品点位差异矩阵和待确认问题清单，锁定 HACS 开发基线。
2. 实现明确的协议读取、派生值和实体映射。
3. 完成周期统计持久化、告警聚合及分档展示。

5. 备份 Green 后部署候选版本，执行真实设备验收及升级回退测试。
6. 更新点位矩阵、交接文档和已完成/未完成状态。

交付点位差异矩阵、代码、回归测试、待确认清单、Green 验收记录及更新后的交接文档。
